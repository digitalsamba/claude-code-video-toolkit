Release-notes videos with no screen recording

Claude Code reads your app's source, rebuilds the screens as React, and films them with a scripted cursor and camera. Nothing to record, no test data, nothing that goes stale.

Why not record the screen?

A Playwright or screen recording needs a running app, accounts, test data and a clean state, and it breaks on the next UI change. A rebuilt screen is static React: it renders the same every time, shows exactly the state the story needs, and the camera can zoom anywhere without blur.

How it works

  1. Write the narration first, one sentence per item, and generate it (a cloned voice works well).
  2. Rebuild each screen from the app's own components and styles, as a static React page at a fixed canvas size. Claude Code reads the source; you point it at the right files.
  3. Drive it with Stage and Cursor: a browser window, camera keyframes for zoom and pan, and an eased cursor with click ripples. Every click is a frame number looked up from the narration with cue('save'), so when the voice is re-timed the whole scene follows it.
  4. Check the text with qc.py --layout: it opens the composition in a browser and reports text that's too small for a phone, clipped, or under WCAG contrast.

Start

cp -r templates/ds-release-notes projects/my-release
# then, in Claude Code:
Make a release-notes video for these three changes: ...
The app's source is in ~/code/my-app.

The template ships as a finished build, so it renders as is; for your release keep the kits and replace the scenes. The method and its gotchas are in the synthetic-ui-demo skill.
